Sandbox Kit is an SDK. You construct a client with a provider and config; the client calls that provider for create, lifecycle, filesystem, and process work. Application code stays on the shared client surface.

## Client

Credentials are checked on the first provider call, not at construction. Details: [Configuration](/docs/configuration).

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

<ForProvider id="daytona">

```ts
import { daytona } from "@sandbox-kit/daytona";
import { Client } from "@sandbox-kit/sandbox";

await using client = new Client({
  provider: daytona(),
  auth: { apiKey: { key: process.env.DAYTONA_API_KEY! } },
  region: process.env.DAYTONA_TARGET,
  timeout: 120_000, // default client deadline (ms)
});
```

## Sandbox handle

`create` returns a handle. To reopen an existing sandbox, use `get` or `attach`—see [Lifecycle](/docs/lifecycle). Use the handle for lifecycle, filesystem, and process calls.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

<ForProvider id="daytona">

```ts
const sandbox = await client.create({
  source: { image: { reference: "daytonaio/playground:latest" } },
});
console.log(sandbox.id);

await sandbox.filesystem.writeFile("/tmp/note.txt", data);
const result = await sandbox.process.run({ argv: ["echo", "hi"] });
// result: { exitCode, stdout, stderr }
console.log(result);
```

</ForProvider>

## Providers

Each provider is its own package. Pass it into the client. Auth, create defaults, and which lifecycle calls exist depend on the provider; the client methods stay the same.

The client talks to Daytona or Modal directly. There is no separate Kit cloud in the middle.

## Capabilities

Unsupported calls fail before anything reaches the cloud. The cloud can still refuse a supported call for a particular sandbox; that comes back as a provider error.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
import { LifecycleCapability } from "@sandbox-kit/sandbox";

if (!sandbox.supports(LifecycleCapability.Stop)) {
  throw new Error(`sandbox ${sandbox.id} cannot be stopped`);
}
```

  </Tab>
  <Tab value="Go">

```go
import "github.com/sandbox-kit/kit/sdks/go/sandbox"

if !instance.Supports(sandbox.LifecycleCapabilityStop) {
	return fmt.Errorf("sandbox %s cannot be stopped", instance.ID())
}
```

  </Tab>
</Tabs>

## Concurrency

Calls on one handle run one at a time. A second handle for the same sandbox id does not share that queue.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
const ac = new AbortController();
const pending = sandbox.process.run({
  argv: ["sleep", "30"],
  signal: ac.signal,
});
ac.abort(); // rejects the await; handle stays busy until the in-flight call finishes
await pending.catch(() => {});
```

  </Tab>
  <Tab value="Go">

```go
ctx, cancel := context.WithCancel(ctx)
defer cancel()

go func() {
	time.Sleep(10 * time.Millisecond)
	cancel() // ends the wait; handle stays busy until the in-flight call finishes
}()

_, err := instance.Process().Run(ctx, &sandbox.ExecOptions{
	Argv: []string{"sleep", "30"},
})
```

  </Tab>
</Tabs>

## Close

Neither call stops, archives, or deletes the cloud sandbox. Use an explicit lifecycle method for that.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
await client.close(); // local provider connection
await sandbox.close(); // local handle resources only
```

  </Tab>
  <Tab value="Go">

```go
defer client.Close(context.Background()) // local provider connection
_ = instance.Close(context.Background()) // local handle resources only
```

  </Tab>
</Tabs>
