Sandbox Kit is an SDK. You construct a client with a provider and config; the client calls that provider for create, lifecycle, filesystem, and process work. Application code stays on the shared client surface.

## Client

Credentials are checked on the first provider call, not at construction. Details: [Configuration](/docs/configuration).

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

<ForProvider id="daytona">

```ts
import { daytona } from "@sandbox-kit/daytona";
import { Client } from "@sandbox-kit/sandbox";

await using client = new Client({
  provider: daytona(),
  auth: { apiKey: { key: process.env.DAYTONA_API_KEY! } },
  region: process.env.DAYTONA_TARGET,
  timeout: 120_000, // default client deadline (ms)
});
```

## Filesystem

Sandbox paths are absolute. Write, read, copy, list, and remove go through the handle. More: [Filesystem](/docs/filesystem).

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
const body = new TextEncoder().encode("hello from kit\n");
await sandbox.filesystem.writeFile("/tmp/note.txt", body);

const bytes = await sandbox.filesystem.readFile("/tmp/note.txt");
console.log(new TextDecoder().decode(bytes));
```

  </Tab>
  <Tab value="Go">

```go

if err != nil {
	return err
}
```

## Process

Run one command and wait for it to finish. A non-zero exit code is **not** an SDK error—check `exitCode` yourself. More: [Process](/docs/process).

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
const result = await sandbox.process.run({
  argv: ["echo", "hello from kit"],
  workingDirectory: "/tmp",
  environment: { KIT_DEMO: "from-kit" },
  timeout: 5_000,
});
// result: { exitCode, stdout, stderr }
console.log(result);
```

  </Tab>
  <Tab value="Go">

```go
result, err := instance.Process().Run(ctx, &sandbox.ExecOptions{
	Argv:             []string{"echo", "hello from kit"},
	WorkingDirectory: sandbox.Value("/tmp"),
	Environment:      map[string]string{"KIT_DEMO": "from-kit"},
	Timeout:          sandbox.Duration(5 * time.Second),
})
if err != nil {
	return err
}
// result: ExitCode, Stdout, Stderr
fmt.Println(result)
```

  </Tab>
</Tabs>

## Providers

Each provider is its own package. Pass it into the client. Auth, create defaults, and which lifecycle calls exist depend on the provider; the client methods stay the same.

The client talks to Daytona, Modal, or Blaxel directly. There is no separate Kit cloud in the middle.

## Capabilities

Unsupported calls fail before anything reaches the cloud. The cloud can still refuse a supported call for a particular sandbox; that comes back as a provider error.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

<ForProvider id="daytona">

```ts
import { LifecycleCapability } from "@sandbox-kit/sandbox";

if (!sandbox.supports(LifecycleCapability.Stop)) {
  throw new Error(`sandbox ${sandbox.id} cannot be stopped`);
}
```

</ForProvider>

## Concurrency

Calls on **one handle** run one at a time. Starting two awaits does not overlap them—the second waits until the first settles. Abort or cancel rejects your wait promptly; the handle stays busy until the provider call finishes. A second handle for the same sandbox id has its own queue, so those calls can run together.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
// Queued on one handle — `two` starts only after `one` finishes.
const one = sandbox.process.run({ argv: ["echo", "one"] });
const two = sandbox.process.run({ argv: ["echo", "two"] });
const [first, second] = await Promise.all([one, two]);
console.log(first, second);

// Abort ends the wait; the handle stays busy until the provider call settles.
const ac = new AbortController();
const pending = sandbox.process.run({
  argv: ["sleep", "30"],
  signal: ac.signal,
});
ac.abort();
await pending.catch(() => {});
```

<ForProvider id="daytona">

```ts
// Parallel work: another handle for the same id has its own queue.
const other = await client.get(sandbox.id);
await Promise.all([
  sandbox.process.run({ argv: ["echo", "a"] }),
  other.process.run({ argv: ["echo", "b"] }),
]);
```

</ForProvider>

<ForProvider id="modal">

```ts
// Parallel work: another handle for the same id has its own queue.
const other = await client.attach(sandbox.id);
await Promise.all([
  sandbox.process.run({ argv: ["echo", "a"] }),
  other.process.run({ argv: ["echo", "b"] }),
]);
```

</ForProvider>

  </Tab>
  <Tab value="Go">

```go
// Two goroutines still serialize on one handle — the second waits for the first.
errCh := make(chan error, 2)
go func() {
	_, err := instance.Process().Run(ctx, &sandbox.ExecOptions{
		Argv: []string{"echo", "one"},
	})
	errCh <- err
}()
go func() {
	_, err := instance.Process().Run(ctx, &sandbox.ExecOptions{
		Argv: []string{"echo", "two"},
	})
	errCh <- err
}()
for range 2 {
	if err := <-errCh; err != nil {
		return err
	}
}

// Cancel ends the wait; the handle stays busy until the provider call settles.
runCtx, cancel := context.WithCancel(ctx)
defer cancel()
go func() {
	time.Sleep(10 * time.Millisecond)
	cancel()
}()
_, _ = instance.Process().Run(runCtx, &sandbox.ExecOptions{
	Argv: []string{"sleep", "30"},
})
```

## Close

Neither call stops, archives, or deletes the cloud sandbox. Use an explicit lifecycle method for that.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
await client.close(); // local provider connection
await sandbox.close(); // local handle resources only
```

  </Tab>
  <Tab value="Go">

```go
defer client.Close(context.Background()) // local provider connection
_ = instance.Close(context.Background()) // local handle resources only
```

  </Tab>
</Tabs>
