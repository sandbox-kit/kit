Operate on a handle from `create`, or open one by id. Switch Daytona or Modal above for open, destroy, and capability notes.

| Operation                      | Daytona                                    | Modal                                             |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------- |
| Open existing                  | [`get`](#open-a-sandbox) (provider lookup) | [`attach`](#open-a-sandbox) (id only, no lookup)  |
| start / stop / pause / archive | [Supported](#stop-start-pause-and-archive) | Rejected in Kit                                   |
| Destroy                        | [`delete`](#delete)                        | [`terminate`](#terminate) or create-time lifetime |
| Local disconnect               | [`close`](#close-the-client)               | [`close`](#close-the-client)                      |

Check support with `supports` / `Supports` (`LifecycleCapability*` in Go). Unsupported ops fail before the provider call. Daytona may still reject a supported op for a given sandbox.

Calls on one handle run one at a time with filesystem and process. Abort or
deadline rejects the TypeScript `await` (and ends the Go wait), but the handle
stays busy until that provider call settles.

Snippets assume a constructed `client` ([Daytona](/docs/daytona) / [Modal](/docs/modal)).

## Open a sandbox

<ForProvider id="daytona">

`get` loads a sandbox that already exists. `refresh` loads it again. `Attach` is not available.

</ForProvider>

<ForProvider id="modal">

`attach` builds a handle from an id. It does not ask Modal whether that sandbox exists. Modal has no `get` and no `refresh`.

</ForProvider>

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

<ForProvider id="daytona">

```ts
const sandbox = await client.get(process.env.DAYTONA_SANDBOX_ID!);
const info = await sandbox.refresh();
console.log(sandbox.id, info.state);
```

</ForProvider>

<ForProvider id="modal">

```ts
const sandbox = await client.attach(process.env.MODAL_SANDBOX_ID!);
console.log(sandbox.id);
```

</ForProvider>

  </Tab>
  <Tab value="Go">

<ForProvider id="daytona">

```go
instance, err := client.Get(ctx, os.Getenv("DAYTONA_SANDBOX_ID"))
if err != nil {
	return err
}
if err := instance.Refresh(ctx); err != nil {
	return err
}
```

</ForProvider>

<ForProvider id="modal">

```go
instance, err := client.Attach(ctx, os.Getenv("MODAL_SANDBOX_ID"))
if err != nil {
	return err
}
```

</ForProvider>

  </Tab>
</Tabs>

## Stop, start, pause, and archive

<ForProvider id="daytona">

These four calls are Daytona calls. `stop` asks Daytona to stop the sandbox. The sandbox stays available to start again. `start` brings a stopped or archived sandbox back. `pause` keeps memory and stops the sandbox. `archive` moves a retained sandbox into archive storage.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
const sandbox = await client.get(process.env.DAYTONA_SANDBOX_ID!);

if (!sandbox.supports(LifecycleCapability.Stop)) {
  throw new Error(`sandbox ${sandbox.id} cannot be stopped`);
}

const info = await sandbox.stop({ timeout: 60_000 });
console.log(sandbox.id, info.state);
```

`timeout` is milliseconds. Pass `force: true` to request an immediate stop. Check `supports` the same way before `start`, `pause`, or `archive`.

  </Tab>
  <Tab value="Go">

```go
instance, err := client.Get(ctx, os.Getenv("DAYTONA_SANDBOX_ID"))
if err != nil {
	return err
}
if !instance.Supports(sandbox.LifecycleCapabilityStop) {
	return fmt.Errorf("sandbox %s cannot be stopped", instance.ID())
}
if err := instance.Stop(ctx, &sandbox.StopOptions{
	Timeout: sandbox.Duration(time.Minute),
}); err != nil {
	return err
}
```

`Start`, `Pause`, and `Archive` take the same kind of options. Check `Supports` before each one.

  </Tab>
</Tabs>

Daytona decides whether that sandbox can pause, archive, or stop. An ephemeral sandbox can still be removed by the lifetime you set at [create](/docs/create) time.

</ForProvider>

<ForProvider id="modal">

Modal rejects `stop`, `start`, `pause`, and `archive` in Kit. Use [terminate](#terminate) or create-time lifetime policies instead.

</ForProvider>

## Delete

<ForProvider id="daytona">

`delete` removes a Daytona sandbox.

const sandbox = await client.get(process.env.DAYTONA_SANDBOX_ID!);
await sandbox.delete({ timeout: 60_000 });

  </Tab>

instance, err := client.Get(ctx, os.Getenv("DAYTONA_SANDBOX_ID"))

</Tabs>

</ForProvider>

## Terminate

<ForProvider id="modal">

`terminate` finishes a Modal sandbox. It is not a stop, and it is not a delete. A maximum lifetime or an idle timeout set at [create](/docs/create) time also ends the sandbox.

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
const sandbox = await client.attach(process.env.MODAL_SANDBOX_ID!);

if (!sandbox.supports(LifecycleCapability.Terminate)) {
  throw new Error(`sandbox ${sandbox.id} cannot be terminated`);
}

const exit = await sandbox.terminate({ wait: true, timeout: 60_000 });
console.log(sandbox.id, exit.exitCode);
```

`wait: true` polls until the sandbox exits or the timeout fires. The timeout is how long the client waits. Modal does not receive that duration as its own terminate timeout.

  </Tab>
  <Tab value="Go">

```go
instance, err := client.Attach(ctx, os.Getenv("MODAL_SANDBOX_ID"))
if err != nil {
	return err
}
if !instance.Supports(sandbox.LifecycleCapabilityTerminate) {
	return fmt.Errorf("sandbox %s cannot be terminated", instance.ID())
}
exit, err := instance.Terminate(ctx, &sandbox.TerminateOptions{
	Wait:    sandbox.Value(true),
	Timeout: sandbox.Duration(time.Minute),
})
if err != nil {
	return err
}
fmt.Println(exit.GetExitCode())
```

  </Tab>
</Tabs>

</ForProvider>

<ForProvider id="daytona">

Daytona rejects `terminate`. Use [delete](#delete) or create-time lifetime policies instead.

</ForProvider>

## Close the client

<Tabs groupId="language" items={['TypeScript', 'Go']} persist>
  <Tab value="TypeScript">

```ts
await client.close();
```

Prefer `await using` when the client lifetime matches the block. Client dispose closes the connection. Handle dispose does not stop the sandbox.

  </Tab>
  <Tab value="Go">

```go
defer client.Close(context.Background())
```

`Sandbox.Close` does not stop or delete the sandbox. Later calls on that handle still reach the provider.

  </Tab>
</Tabs>

## Read the state

`info.state` is the portable state; the provider's native string sits beside it. After a lifecycle call, refresh or re-fetch before assuming the sandbox is stopped or gone. A failed call can still mean the provider already changed state. See [Errors](/docs/errors).
